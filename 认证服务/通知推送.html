通知推送使用说明

通知推送使用说明

1. 概述

通知推送功能用于向认证用户或指定内网终端主动发送系统消息，是网络管理系统中实现信息触达、业务提醒与到期预警的重要能力。该功能支持按不同业务场景配置实时通知、定期通知、到期通知、拨号用户过期通知等多种推送方式，可将运维公告、服务提醒、到期预警等信息按需发送给目标用户。

  • 实时通知：用于发送即时性、单次触发的通知消息，适用于紧急告警、临时公告、维护提示等场景。
  • 定期通知：用于按预设周期自动重复推送通知，适用于日报、周报、定时提醒、定期任务结果通知等场景。
  • 到期通知：用于在资源、服务或账号到期前按设定提前天数进行提醒，帮助管理员提前告知用户，减少因到期造成的服务中断。
  • 拨号用户过期通知：用于专门向拨号认证用户发送过期提醒，并支持按白名单 IP 或白名单域名进行排除，便于精细化管理特殊用户群体。

通知推送功能支持自定义通知内容、跳转页面、接收对象、推送周期、提醒时间和倒计时等参数，并支持在通知内容中插入动态变量（如 $user、$name、$date），以生成更具针对性的个性化提示信息。通过合理使用该模块，可提升系统运维主动性、优化用户体验并增强业务提醒的准确性。

2 参数解释与操作导航

2.1 界面布局

依次点击【认证服务】>【通知推送】，进入通知推送页面。

通知推送页面采用多标签页布局，主要包含【实时通知】、【定期通知】、【到期通知】和【拨号用户过期通知】等功能模块。不同标签页对应不同的通知策略类型，管理员可根据实际业务场景选择对应页面进行配置。

2.2 实时通知

实时通知用于向目标用户立即发送一次性通知消息，支持配置通知内容、跳转页面、接收对象、目标 IP 地址或 IP 分组，以及通知显示倒计时等参数，适用于紧急告警、临时维护公告、服务中断提醒等场景。

2.2.1 实时通知主页面

实时通知页面如下图所示：

实时通知主页面

实时通知页面为即时消息的配置与发送页面，管理员可在该页面编辑通知内容、设置跳转页面、选择接收对象，并通过 IP 设置或 IP 分组精确指定接收范围。页面同时提供 IP 批量导入与单条添加能力，便于快速完成目标对象配置。

功能按钮

  • 批量（IP 设置区域）：批量导入多个 IP 地址到推送对象列表；
  • 添加（IP 设置区域）：新增单个 IP 地址到推送对象列表。

2.2.2 实时通知参数配置

参数解释表

参数名称详细说明
通知内容需要推送给目标用户的通知正文，支持富文本内容和动态变量。可使用 $user 表示用户名、$name 表示真实姓名、$date 表示日期。适合用于构造个性化提醒内容。
跳转页面用户点击通知后跳转的目标页面地址。通常填写业务系统页面、续费页面、公告详情页等 URL。
拨号用户勾选后，通知将推送给所有拨号认证用户。适用于统一面向全部拨号用户发布公告的场景。
列表中的内网用户勾选后，通知只发送给下方已配置的内网 IP 地址或所选 IP 分组中的用户。
IP地址指定需要接收通知的内网终端 IP 地址。可用于精确指定单个或多个终端作为通知对象。
IP分组选择系统中预先建立好的 IP 分组，分组中的所有 IP 对应用户都将作为通知接收对象。
显示倒计时*配置通知展示的持续时间，单位为秒。若设置为 0，通常表示不自动关闭，需用户手动确认。配置不合理可能影响通知关闭行为。

注：带*号的项为必填项。

2.3 定期通知

定期通知用于按设定周期自动重复推送通知消息，支持创建多个任务并进行启用、停用、编辑、删除和批量管理。该功能适用于周期性报告推送、运维提醒、定时公告等场景。

2.3.1 定期通知主页面

定期通知页面如下图所示：

定期通知列表页面

定期通知页面为周期任务的管理控制台，支持对现有通知任务进行添加、编辑、启用、停用、删除、预览等操作；列表中通常展示任务名称、周期信息、状态等关键字段，便于管理员统一查看和维护所有周期性通知任务。

功能按钮

  • 添加：打开“定期通知-编辑”界面，创建新的定期通知任务；
  • 编辑（列表操作列）：修改对应通知任务的名称、通知内容、推送周期、接收对象等参数；
  • 启用/停用（列表操作列）：启用或暂停指定通知任务；
  • 删除（列表操作列）：删除指定通知任务及其配置；
  • 预览（列表操作列）：预览当前通知的展示效果和变量替换结果。

2.3.2 添加/编辑定期通知

点击主页面【添加】按钮，或在任务列表中点击【编辑】，可打开定期通知新增/编辑页面。该页面用于配置通知任务的名称、通知内容、推送周期、推送时间、接收对象、IP 设置、IP 分组、备注及显示倒计时等参数。

定期通知新增/编辑页面如下图所示：

定期通知新增/编辑页面

参数解释表

参数名称详细说明
名称*定期通知任务名称，用于区分不同通知策略。建议采用能够反映用途的命名方式，如“数据库备份日报”“每周维护提醒”等。
通知内容周期性推送的通知正文，支持富文本和动态变量，适合编写报表提醒、巡检结果提醒等内容。
跳转页面用户点击通知后跳转的目标页面地址，用于承载详细信息或后续操作入口。
推送周期配置通知的重复周期，通常支持按“周”或“日”进行设置。若选择“周”，还需结合具体星期配置使用。
推送时间配置通知的具体发送时间点。可根据业务要求设置单个或多个时间点。
接收对象选择通知的接收用户类型。可面向全部拨号用户，或面向列表中的内网用户。
IP设置当接收对象选择列表中的内网用户时，用于逐条添加或批量导入目标 IP 地址。
IP分组选择系统已存在的 IP 分组，实现按组推送通知。
备注对通知任务进行补充说明，便于后续维护和识别任务用途。
显示倒计时*配置通知在用户侧展示的持续时间，单位为秒。若设置为 0，通常需用户手动确认关闭。

注：带*号的项为必填项。

在定期通知主页面中勾选多个任务后，可进入批量操作状态，对选中的任务执行统一管理操作。

定期通知批量操作页面如下图所示：

定期通知批量操作页面

功能按钮

  • 启用：批量启用已选中的通知任务；
  • 停用：批量停用已选中的通知任务；
  • 删除：批量删除已选中的通知任务配置。

2.4 到期通知

到期通知用于针对资源、服务或账号到期场景进行预警，管理员可设置是否启用到期提醒、通知内容、跳转页面、提前提醒天数、提醒时间段及显示倒计时等参数，从而在到期前自动向目标用户发送提醒消息。

到期通知页面如下图所示：

到期通知配置页面

到期通知页面为到期类提醒的集中配置页面，用于统一设置提醒开关、提醒模板、触发时机和展示方式。配置完成后需保存方可生效。

参数解释表

参数名称详细说明
到期提醒是否启用到期提醒功能。启用后，系统将在符合条件时自动触发提醒通知。
$user通知内容中的动态变量，自动替换为接收用户的登录账号。
$name通知内容中的动态变量，自动替换为接收用户的真实姓名。
$date通知内容中的动态变量，自动替换为对应的到期日期。
跳转页面用户点击通知后跳转的目标页面地址。可用于引导用户进入续费或详情页面。
提前到期提醒*配置系统在到期前多少天开始发送提醒。应根据业务需要合理设置提前量。
定时提醒时段配置每天触发提醒的具体时间点。可根据用户作息和业务习惯选择合适时段。
显示倒计时*配置通知显示时长，单位为秒。若设置为 0，则通常需要用户手动确认关闭通知。

注：带*号的项为必填项。

功能按钮

  • 通知预览：预览到期通知的最终展示效果；
  • 保存：保存当前到期通知配置并使其生效。

2.5 拨号用户过期通知

拨号用户过期通知用于对拨号认证用户的账号到期进行专项提醒，并支持通过白名单公网 IP 与白名单域名排除特定对象，适用于宽带账号、拨号服务到期提醒等场景。

拨号用户过期通知页面如下图所示：

拨号用户过期通知配置页面

拨号用户过期通知页面为拨号用户到期提醒的专项配置页面，用于统一设置通知内容及白名单排除条件。配置保存后，系统可根据拨号用户到期状态自动触发提醒。

参数解释表

参数名称详细说明
通知内容拨号用户账号到期提醒的通知正文，支持使用 $user、$name、$date 等动态变量生成个性化内容。
白名单公网IP配置无需接收拨号用户过期通知的公网 IP 地址。位于白名单中的目标将被排除在通知范围之外。
白名单域名配置无需接收拨号用户过期通知的域名。与白名单公网 IP 一样，用于排除特殊对象。

功能按钮

  • 通知预览：预览拨号用户过期通知的展示效果；
  • 保存：保存当前拨号用户过期通知配置。

3. 核心运维与操作流程

通知推送的运维可按“选择通知类型 -> 配置通知参数 -> 预览验证 -> 保存/启用 -> 日常巡检”的顺序进行管理。不同类型通知虽然应用场景不同，但整体维护思路一致。

3.1 通知配置通用流程

  1. 访问功能页面：进入【认证服务】>【通知推送】，根据业务场景选择对应标签页，如需要立即发送的消息选择“实时通知”，需要周期性发送的消息选择“定期通知”，到期提醒类业务选择“到期通知”或“拨号用户过期通知”。
  2. 编辑通知内容：在对应页面填写通知正文，并根据需要插入动态变量（如 $user、$name、$date），提升消息针对性和可读性。
  3. 配置接收对象：
  • 面向所有拨号认证用户时，可直接选择“拨号用户”；
  • 面向特定内网终端时，应选择“列表中的内网用户”，并通过“IP 设置”或“IP 分组”指定接收范围。
  1. 设置触发与展示规则：根据通知类型配置跳转页面、推送周期、推送时间、提前提醒天数、定时提醒时段和显示倒计时等参数。
  2. 预览与保存：如页面提供“通知预览”，建议先进行预览确认；检查内容、变量、目标对象和时间设置无误后，再点击“保存”使配置生效。

3.2 定期通知管理流程

  1. 新增任务：在【定期通知】页面点击【添加】，创建新的周期性通知任务。
  2. 维护任务参数：填写任务名称、通知内容、周期、时间、接收对象和备注等信息。
  3. 启用任务：保存任务后，确认任务处于启用状态，确保系统按计划执行推送。
  4. 编辑与停用：当推送内容、时间或对象发生变更时，可通过列表中的【编辑】修改参数；如通知暂不需要推送，可通过【停用】暂停任务。
  5. 批量维护：当存在多个同类任务需要统一启停或删除时，可通过批量勾选方式进行集中处理。

3.3 到期类通知维护要点

  • 到期通知：重点检查“提前到期提醒”和“定时提醒时段”配置是否符合业务要求，避免提醒过早或遗漏。
  • 拨号用户过期通知：应定期维护白名单公网 IP 和白名单域名，防止不应接收提醒的对象被误通知，或应提醒对象被误排除。
  • 变量内容校验：对于依赖 $user、$name、$date 的通知模板，建议在上线前进行预览或抽样验证，确保替换结果正确。

4. 常见问题与故障排除

问题现象可能原因排查步骤与解决方案
用户未收到通知1. 接收对象配置错误。2. IP 地址或 IP 分组未正确设置。3. 任务未启用。4. 用户被白名单排除。1. 检查接收对象：确认已正确选择“拨号用户”或“列表中的内网用户”。2. 检查目标范围：若使用 IP 设置或 IP 分组，确认配置对象准确且有效。3. 检查任务状态：在定期通知列表中确认任务处于启用状态。4. 检查白名单：针对拨号用户过期通知，确认目标对象未被加入白名单公网 IP 或白名单域名。
通知内容中的变量未正确替换1. 变量书写格式错误。2. 用户信息不完整。1. 检查变量格式：确认变量使用 $user、$name、$date 等标准格式。2. 检查基础数据：核对系统中用户真实姓名、账号、到期时间等信息是否已完整录入。
定期通知未按计划发送1. 任务处于停用状态。2. 推送周期或推送时间设置错误。3. 系统时间异常。1. 检查任务状态：确认任务已启用。2. 检查周期设置：核对推送周期和推送时间是否符合预期。3. 检查系统时间：确认设备时间准确，避免因系统时间偏差导致任务触发异常。
通知弹出后长期不消失显示倒计时配置为 0 或配置不合理。1. 检查倒计时参数：确认“显示倒计时”是否设置为合理值。2. 按需调整：若不希望通知长期停留，可设置明确的自动关闭时长。
批量操作未生效1. 未勾选任务。2. 页面状态未刷新。3. 操作过程异常中断。1. 检查勾选状态：确认已正确选中目标任务。2. 刷新后重试：刷新页面重新执行批量启用、停用或删除操作。3. 核查结果：查看列表状态是否发生实际变化。
拨号用户过期通知对部分用户未生效目标用户被配置在白名单中。1. 检查白名单配置：确认目标用户对应的公网 IP 或域名是否被加入白名单。2. 调整排除策略：若需恢复提醒，应删除对应白名单条目后重新保存。

高级注意事项：

  • 倒计时配置影响展示行为：若显示倒计时设置为 0，通知可能不会自动关闭，部署前应结合实际业务需求谨慎设置。
  • 接收对象应最小化配置：对于仅面向部分用户的通知，建议优先使用精确 IP 或 IP 分组配置，避免造成不必要的消息打扰。
  • 到期提醒应提前验证：对于重要业务的到期提醒，建议在正式启用前先验证变量替换、提醒时间与接收对象的准确性。
  • 白名单需定期审查：拨号用户过期通知中的白名单配置会直接影响通知覆盖范围，应纳入日常维护检查项。
