智能流控使用说明

1 概述

智能流控模块是 iKuai OS V4 网络管理系统的核心功能之一，通过对网络流量进行精细化管控，实现以下目标：

  • 带宽保障：为关键业务（如视频会议、ERP 系统）分配专属带宽，避免被非关键流量（如下载、浏览）抢占。
  • 流量整形：限制非关键应用的带宽使用，防止单一用户或应用耗尽网络资源。
  • 优先级调度：基于业务重要性、用户角色等维度，对流量进行优先级排序，确保高优先级流量优先转发。
  • 可视化监控：实时展示流量统计、连接数、带宽利用率等指标，辅助网络优化决策。

3 核心运维与操作流程

3.3.1 日常监控与策略验证

目标：通过可视化界面监控流控策略的执行状态，验证带宽限制、优先级调度是否生效。

操作流程：

  1. 流量统计监控：
  • 进入【流控线路】标签页，查看“上行”“下行”列的实时流量（需设备支持实时统计）。
  • 结合【终端独立限速】标签页的“上行”“下行”参数，验证终端实际带宽是否受限于配置。
  1. 策略生效验证：
  • 对于域名策略：在终端访问绑定的域名（如 www.baidu.com），使用测速工具（如 Speedtest）验证带宽是否符合配置。
  • 对于 IP/MAC 分组策略：在终端（绑定的 IP/MAC）上进行大文件下载/上传，验证带宽是否被限制。
  1. 优先级验证：
  • 同时启动高优先级（如优先级 0）和低优先级（如优先级 10）的业务（如视频会议+下载），使用抓包工具（如 Wireshark）分析流量的转发顺序和带宽分配。

3.3.2 流控策略创建（以 VLAN 流控为例）

目标：为指定 VLAN 配置带宽限制和优先级，保障关键业务流量。

操作流程：

  1. 需求分析：明确需管控的 VLAN（如“研发部 VLAN”）、绑定的物理接口（如 lan1）、IP 网段（如 192.168.40.0/24）、带宽限制（如上行 10Mbps、下行 100Mbps）、优先级（如 0-最高）。
  2. 参数转换：将 IP 网段转换为子网掩码（如 192.168.40.0/24 对应 255.255.255.0），带宽单位转换为 KB/s（如 10Mbps=1280KB/s，100Mbps=12800KB/s）。
  3. 添加策略：
  • 进入【流控线路】标签页，点击【添加】按钮。
  • 填写参数：vlanID=40、vlan 名称=研发部 VLAN、IP=192.168.40.0、子网掩码=255.255.255.0、线路=lan1、上行=1280、下行=12800、优先级=0。
  • 点击【保存】，策略生效。
  1. 验证：在研发部终端上进行大文件上传/下载，使用测速工具验证带宽是否符合配置。

3.3.3 域名流控策略创建

目标：限制特定域名的带宽使用，防止非关键应用（如视频网站）占用过多带宽。

操作流程：

  1. 需求分析：明确需管控的域名（如 www.iqiyi.com）、带宽限制（如上行 5Mbps、下行 50Mbps）、生效时间（如“周一至周五 09：00-18：00”）。
  2. 参数转换：带宽单位转换为 KB/s（如 5Mbps=640KB/s，50Mbps=6400KB/s）。
  3. 添加策略：
  • 进入【优先域名设置】标签页，点击【添加】按钮。
  • 填写参数：名称=视频网站限流、域名=www.iqiyi.com、上行=640、下行=6400、生效时间=周一至周五 09：00-18：00。
  • 点击【保存】，策略生效。
  1. 验证：在终端访问 www.iqiyi.com，使用测速工具验证带宽是否符合配置。

3.4 终端独立限速策略创建

目标：为特定终端（IP/MAC）分配独立带宽，避免其影响其他终端。

操作流程：

  1. 需求分析：明确需管控的终端（如 IP 192.168.40.10，MAC 00：11：22：33：44：55）、带宽限制（如上行 2Mbps、下行 20Mbps）、优先级（如 5）、生效时间（如“全天”）。
  2. 参数转换：带宽单位转换为 KB/s（如 2Mbps=256KB/s，20Mbps=2560KB/s）。
  3. 创建 IP/MAC 分组：
  • 进入【终端独立限速】标签页，点击【IP 分组】按钮。
  • 输入分组名称（如“研发部终端组”），添加 IP 192.168.40.10，点击【保存】。
  1. 添加限速策略：
  • 进入【终端独立限速】标签页，点击【添加】按钮。
  • 填写参数：名称=研发部终端限速、IP/MAC 分组=研发部终端组、上行=256、下行=2560、优先级=5、生效时间=全天。
  • 点击【保存】，策略生效。
  1. 验证：在目标终端上进行大文件下载/上传，使用测速工具验证带宽是否符合配置。

3.5 优先级调整与冲突解决

目标：通过调整策略优先级，确保高优先级业务（如视频会议）的带宽保障。

操作流程：

  1. 识别冲突：通过流量监控发现高优先级业务（如 video.conference.com）的带宽被低优先级业务（如下载）抢占。
  2. 调整优先级：
  • 进入【优先域名设置】标签页，找到低优先级策略（如“下载限流”），点击【编辑】，将优先级从 5 调整为 10。
  • 进入【终端独立限速】标签页，找到占用带宽的终端策略，点击【编辑】，将优先级从 5 调整为 10。
  • 确保高优先级策略（如“视频会议保障”）的优先级为 0（最高）。
  1. 验证：再次启动高优先级和低优先级业务，验证带宽分配是否符合预期。

3.6 基于时间的动态流控

最佳实践：结合业务高峰/低谷，动态调整流控策略。例如：

  • 工作日 09：00-18：00，限制非关键应用（如下载）的带宽为 1Mbps。
  • 工作日 18：00-次日 09：00，取消非关键应用的限制，保障用户体验。

操作流程：

  1. 创建两条域名策略：“工作日限流”（生效时间：周一至周五 09：00-18：00，带宽 1Mbps）和“非工作时限流”（生效时间：其余时间，带宽无限制）。
  2. 确保两条策略的优先级合理（“工作日限流”优先级更高）。

3.7 应用层流控增强

最佳实践：结合应用识别技术（如 DPI），对加密流量（如 HTTPS）进行深度识别，确保流控策略的精准性。例如：

  • 识别“腾讯会议”“Zoom”等视频会议应用，保障其带宽。
  • 识别“迅雷”“BT”等 P2P 下载应用，严格限制其带宽。

操作流程：

  1. 在流控设备中启用 DPI 功能，更新应用识别库。
  2. 创建基于应用的流控策略，为视频会议应用分配高优先级和保障带宽，为 P2P 下载应用分配低优先级和限制带宽。

3.8 故障切换与冗余

最佳实践：在多线路（WAN）环境下，配置流控策略的故障切换，确保网络中断时业务不中断。例如：

  • 当主 WAN 口（wan1）故障时，自动切换到备用 WAN 口（wan2），并调整流控策略的带宽限制。

操作流程：

  1. 在【内外网设置】中配置 WAN 口冗余（如负载均衡+故障切换）。
  2. 在流控策略中，将“线路”参数设置为“所有 WAN 口”，或针对不同 WAN 口配置独立的流控策略。
  3. 测试 WAN 口故障切换，验证流控策略是否自动适配新线路。

3.4 常见问题与故障排除

3.4.1 流控策略不生效

故障现象：配置的流控策略未对目标流量产生限制。

可能原因：

  1. 策略配置错误：IP 网段、VLAN ID、域名格式等参数错误。
  2. 策略冲突：多条策略的优先级配置不合理，导致低优先级策略覆盖高优先级策略。
  3. 设备兼容性问题：部分终端/应用（如 P2P 下载工具）可能绕过流控（需结合应用层管控）。
  4. 缓存未刷新：终端或交换机的 ARP/DHCP 缓存未更新，导致流量未经过流控设备。

排查步骤：

  1. 验证参数配置：检查策略的 IP 网段、VLAN ID 等参数是否与实际网络一致。
  2. 检查优先级：确保高优先级策略的优先级数值小于低优先级策略。
  3. 清除缓存：在终端执行 ipconfig /flushdns（Windows）或 sudo killall -HUP mDNSResponder（Mac），在交换机执行 clear arp-cache。
  4. 测试基础连通性：在终端 ping 流控设备的 IP，确认流量经过流控设备。

4.2 带宽限制不准确

故障现象：终端实际带宽与配置的带宽限制存在偏差（如配置 10Mbps，实际达到 15Mbps）。

可能原因：

  1. 单位转换错误：配置时未正确转换带宽单位（如将 10Mbps 误算为 12800KB/s，实际应为 1280KB/s）。
  2. 多网卡/多线路分流：终端通过多个网卡或线路访问网络，流控策略仅限制其中一条线路。
  3. 协议识别误差：部分应用（如 HTTPS 加密流量）的协议识别不准确，导致带宽统计偏差。

排查步骤：

  1. 验证单位转换：重新计算带宽单位（1Mbps=128KB/s），确认配置参数正确。
  2. 检查线路绑定：确认流控策略绑定的线路是终端的主要访问路径，或配置多线路聚合流控。
  3. 更新协议库：在流控设备中启用 DPI 功能，更新应用协议识别库，确保流控策略的精准性。

3.4.3 策略导入失败

故障现象：导入策略配置文件时，系统提示“参数错误”或“导入失败”。

可能原因：

  1. 文件格式错误：CSV/TXT 文件的格式不符合要求（如分隔符错误、字段缺失）。
  2. 参数冲突：导入的策略与现有策略存在 IP/VLAN ID 冲突。
  3. 版本不兼容：导入的配置文件来自低版本系统，与新版本不兼容。

排查步骤：

  1. 验证文件格式：参考系统导出的模板文件，确保导入文件的字段、分隔符、编码（如 UTF-8）正确。
  2. 检查参数冲突：导入前，手动检查策略的 IP、VLAN ID 等参数是否与现有策略冲突。
  3. 版本兼容性：查阅系统版本说明，确认导入的配置文件版本与当前系统兼容，必要时升级系统或调整配置文件。
