路由对象使用说明

1 概述

路由对象是 iKuai OS V4 中用于统一维护网络流量匹配条件的基础模块，位于【网络配置】之下。该模块通过将 IP 地址、MAC 地址、时间、域名、协议及端口等条件抽象为可复用的“对象”或“分组”，为分流策略、访问控制、终端管理及其他依赖匹配条件的功能提供统一引用基础。

在日常运维场景中，路由对象的主要价值体现在以下几个方面：

  • 统一沉淀匹配条件：将常用的网段、设备、时间段、域名和协议条件集中管理，避免在多个策略页面重复逐项填写；
  • 提升策略复用能力：已创建的对象可在多个策略模块中重复引用，便于策略标准化和批量维护；
  • 降低配置出错概率：通过对象化管理，将复杂条件拆分为可读、可维护的独立条目，便于核对与复审；
  • 便于运维审计与清理：通过“被引用次数”等字段，可判断某对象是否仍在被其他策略使用，从而辅助清理无效配置；
  • 支持多维度匹配：模块支持 IP 分组、MAC 分组、时间计划、域名分组、协议分组和端口分组等多类对象，能够满足多样化的策略匹配需求。

路由对象本身主要负责对象定义与维护，不直接决定最终放行、分流、限速或拦截动作。管理员通常需要先在本模块中完成对象创建，再在分流策略、访问控制或其他业务模块中引用这些对象，形成完整的网络策略。

2 参数解释与操作导航

2.1 访问路径

  1. 终端接入设备管理网络；
  2. 在浏览器中输入设备管理地址并登录系统；
  3. 在左侧导航栏中依次点击 【网络配置】 > 【路由对象】；
  4. 进入路由对象管理页面后，可根据对象类型切换到对应分组页面进行查看和维护。

2.2 页面结构与界面布局

路由对象页面采用“对象类型一级标签 + 对象子类型二级标签/独立页面”的组织方式。页面上方提供不同对象分类入口，中部为对象列表区域，列表上方提供添加、导入、导出等常用操作按钮，列表中展示对象名称、对象类型、对象内容摘要、被引用次数及操作项。

路由对象主页面如下图所示：

路由对象主页面

功能区域说明

  • 对象分类标签区：用于在 IP 分组、MAC 分组、时间计划、域名分组、协议分组、端口分组之间切换；
  • 对象子标签区：在 IP 分组场景下，可进一步切换 IPv4 与 IPv6；
  • 工具按钮区：用于执行添加、导入、导出等常用管理操作；
  • 对象列表区：用于展示当前分类下的对象信息及其引用情况；
  • 操作列：用于对单个对象执行编辑、删除等维护操作；
  • 帮助入口：用于查看该页面相关帮助说明。

2.3 IP 分组

IP 分组用于集中管理基于 IP 地址的对象，可作为分流策略、访问控制及其他网络策略的匹配条件。IP 分组支持按 IPv4 和 IPv6 两类对象分别维护，便于在不同协议栈环境下进行独立管理。

2.3.1 IPv4 分组

IPv4 分组页面用于维护 IPv4 地址对象。管理员可在该页面创建单个 IP、多个离散 IP、连续地址段或其他 IPv4 目标集合，并将其作为策略中的匹配对象使用。

IPv4 分组页面如下图所示：

IPv4 分组

参数解释表

参数名称详细说明
分组名称当前 IP 分组对象的名称，用于区分不同业务、部门、网段或用途。
分组类型当前对象所属的 IP 分组类型，用于区分 IPv4 分组或 IPv6 分组。
IP当前分组中包含的一个或多个 IP 地址、地址段或摘要内容；当成员较多时，列表中通常以摘要方式显示。
被引用次数当前对象被其他策略或功能模块引用的次数，用于判断对象是否仍在使用中。
操作当前对象可执行的操作项，如编辑、删除等。

功能按钮说明

  • IPv4：切换到 IPv4 分组对象列表；
  • IPv6：切换到 IPv6 分组对象列表；
  • 添加：新增 IP 分组对象；
  • 导入：通过文件方式批量导入 IP 分组对象；
  • 导出：导出当前对象列表，便于备份、迁移或审计；
  • 编辑：修改当前对象的名称、成员或备注等内容；
  • 删除：删除当前对象；删除前应确认该对象未被关键策略引用。

IPv6 分组页面用于维护 IPv6 地址对象，适用于基于 IPv6 地址或地址前缀进行策略匹配的场景。其页面结构与 IPv4 分组基本一致，差异主要体现在对象内容类型由 IPv4 地址切换为 IPv6 地址或地址前缀。

3 核心运维与操作流程

3.1 日常监控与对象管理

目标：通过路由对象界面监控各类对象的配置状态，确保对象配置正确且处于启用状态。

操作流程：

  1. 对象状态监控：
  • 进入路由对象主界面，查看顶栏统计信息，了解各类对象的配置数量
  • 检查各标签页中对象的启用状态，确保关键对象处于启用状态
  • 使用搜索功能快速定位特定对象
  1. 对象配置验证：
  • 对于IP地址对象：验证IP地址和子网掩码配置是否正确
  • 对于MAC地址对象：验证MAC地址格式和设备名称是否准确
  • 对于时间计划对象：验证时间范围和重复周期是否符合业务需求
  • 对于域名对象：验证域名格式和匹配类型是否正确
  • 对于协议组对象：验证包含的协议是否完整
  • 对于端口分流对象：验证端口范围和目标地址是否正确
  1. 对象引用检查：
  • 在分流策略、访问控制等高级功能中检查路由对象的引用情况
  • 确认未被引用的对象是否需要保留或清理

4 常见问题与故障排除

问题现象可能原因排查与解决步骤
对象创建后无法在策略页面找到1. 对象未保存成功；2. 创建在错误的对象分类下；3. 目标策略模块只支持特定类型对象。1. 返回路由对象列表确认对象是否存在；2. 检查对象创建位置是否正确，如 IP 分组、时间计划、协议分组等；3. 核对目标策略页面支持引用的对象类型。
导入后对象内容不完整或格式异常1. 导入文件格式不符合要求；2. 成员字段格式不规范；3. 导入模板与对象类型不匹配。1. 按系统要求重新整理导入文件；2. 检查 IP、MAC、域名、端口等内容格式；3. 按对象分类分别导入，避免混用模板。
删除对象时担心影响现网策略对象可能仍被其他策略模块引用。1. 先查看对象的“被引用次数”；2. 如引用次数不为 0，应先排查依赖策略；3. 替换或移除引用关系后，再执行删除。
策略匹配结果不符合预期1. 选错对象类型；2. 对象成员录入不完整；3. 时间、协议、端口等条件与实际业务不一致。1. 重新核对对象内容；2. 检查是否引用了错误对象；3. 根据实际业务流量补充或修正对象成员。
同一业务需要同时按多个条件匹配单个对象类型无法覆盖全部条件。1. 分别创建 IP、时间、协议、域名等对象；2. 在具体策略页面进行组合引用；3. 保持对象命名清晰，便于后续维护。
对象很多，后续难以区分和维护命名规则不统一，备注不完整。1. 建议按部门、业务、区域、用途建立命名规范；2. 为关键对象补充备注；3. 定期清理无引用对象，降低列表复杂度。
