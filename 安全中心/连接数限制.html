连接数限制使用说明

1 概述

连接数限制是 iKuai OS V4 安全中心中的终端连接行为控制功能,主要用于限制指定内网终端或终端分组的最大连接数,避免单个设备因异常访问、持续高并发请求或恶意行为占用过多会话资源,从而影响其他终端的正常上网体验。

连接数限制页面当前以规则列表方式统一管理所有策略。管理员可按名称维护规则,并为指定内网地址、IP 分组和协议类型设置连接数上限及生效周期,以实现对不同终端对象的差异化连接控制,适合在办公网络、家庭网络、IoT 终端管控及异常终端隔离等场景中使用。

其核心作用主要包括:

  • 终端连接数量限制:为指定内网终端设置最大连接数阈值,防止个别设备长期占用大量连接资源;
  • 按对象精细控制:支持通过单个 IP、多 IP 地址和 IP 分组方式定义规则作用范围;
  • 按协议分类限制:支持为不同协议类型配置不同的连接限制策略;
  • 按时间周期生效:支持结合按周循环和时间段设置规则生效时间;
  • 集中运维管理:支持添加、导入、导出、编辑、复制、启用和删除等维护操作,便于规则的持续管理与批量调整。

2 参数解释与操作导航

2.1 界面布局

依次点击【安全中心】>【连接数限制】,进入连接数限制页面。连接数限制功能用于对指定终端对象的最大连接数进行控制,适用于限制异常终端、高并发终端和特定设备组的网络连接行为。

管理员可在列表中查看当前所有规则,并通过页面上方按钮新增、导入和导出规则,或对单条规则执行编辑、复制、启用和删除等操作。

2.2 连接数限制页面

2.2.1 连接数限制列表页

连接数限制列表页用于展示当前已配置的连接数限制规则,支持查看规则状态及核心字段,并可对规则进行新增、导入、导出和单条维护操作。

连接数限制列表页如下图所示:

连接数限制列表页面

参数解释表

参数名称详细说明
名称用于显示当前连接数限制规则名称,便于管理员区分不同用途的策略。
内网地址用于显示规则作用的终端范围,可为单个 IP、多个 IP 或 IP 分组。
协议用于显示当前规则匹配的协议类型,如"任意"或指定协议。
连接数用于显示当前规则允许的最大连接数阈值。
周期用于显示规则的生效周期和时间段,如按周循环、全天生效等。

操作用于提供编辑、复制、启用和删除等维护入口。

功能按钮说明

  • 添加:用于创建新的连接数限制规则;
  • 导入:用于批量导入连接数限制规则;
  • 导出:用于导出当前连接数限制规则配置;
  • 编辑(操作列):用于修改指定规则的参数;
  • 复制(操作列):用于复制指定规则并快速生成相似规则;
  • 启用/停用(操作列):用于启用或停用当前规则;
  • 删除:用于移除当前规则。

2.2.2 连接数限制新增页面

点击【添加】按钮，可进入连接数限制新增页面。管理员可在该页面中设置名称、内网地址、IP 分组、协议、连接数、生效时间和备注等内容，以完成新规则创建。

参数解释表

参数名称详细说明
名称*用于填写当前规则名称，建议结合终端对象和用途进行命名。
IP设置用于设置当前规则作用的内网地址，支持逐条添加或批量添加多个 IP。
IP分组用于选择已创建的 IP 分组，规则将对该分组内的设备统一生效。
协议*用于设置当前规则匹配的协议类型。
连接数*用于设置当前规则允许的最大连接数，超过阈值后新连接将受到限制。
生效时间*用于设置规则的生效时间范围。

周期用于在按周循环模式下选择规则生效的星期。
备注用于填写规则的补充说明，便于后续维护和识别。

功能按钮说明

  • 批量：用于批量添加内网地址；
  • 添加：用于逐条添加内网地址；
  • 保存：用于保存当前连接数限制规则配置；
  • 取消：用于放弃当前配置并返回列表页面。

2.2.3 连接数限制批量操作

在连接数限制列表页中勾选多条规则后,可进行批量维护操作,以提高规则集中管理效率。该场景通常用于批量启用规则、统一清理旧规则或在大规模调整前统一处理多条策略。

  • 删除(批量):用于批量删除选中的连接数限制规则。

3 核心运维与操作流程

连接数限制规则的日常运维通常包括需求确认、规则创建、效果验证、状态调整和批量维护等环节。为避免误伤正常业务,建议管理员优先对目标终端的实际连接行为进行评估,再逐步下发规则并进行验证。

3.1 规则创建流程

  1. 根据实际需求确认需要限制的终端对象是单个 IP、多个 IP 还是某个 IP 分组。
  2. 进入【连接数限制】页面,点击【添加】。
  3. 依次填写名称、内网地址或 IP 分组、协议、连接数和生效时间等参数。
  4. 如有需要,可补充备注信息,便于后续维护。
  5. 保存规则后,返回列表页检查规则是否已正常生成。

3.2 规则验证与调整流程

  1. 使用命中规则范围内的终端进行实际访问测试,确认连接数限制是否符合预期。
  2. 若规则未生效,优先检查规则是否已启用、生效时间是否覆盖当前时段,以及 IP 设置或 IP 分组是否正确。
  3. 若正常业务受到影响,应优先检查连接数阈值是否设置过低,并根据实际情况适当上调。
  4. 当多条规则并存时,应重点核查不同规则的作用对象是否重叠,避免重复限制造成体验异常。

3.3 批量维护与备份流程

  1. 在列表页中勾选多条规则后,可执行批量启用或批量删除操作。
  2. 在进行批量调整前,建议先通过导出功能备份当前配置。
  3. 如需跨设备迁移或恢复配置,可通过导入功能重新加载已备份规则。

3.4 使用建议

  1. 建议使用具有明确业务含义的名称命名规则,例如按终端类型、区域或用途进行区分。
  2. 对于设备数量较多的场景,建议优先使用 IP 分组统一管理,以减少重复规则数量。
  3. 连接数阈值建议先采用较保守但不影响业务的数值,验证通过后再逐步细化。
  4. 对于办公设备、IoT 设备和高风险终端,建议分别制定不同的连接数限制策略。

4 常见问题与故障排除

问题现象可能原因排查步骤与解决方案
规则配置后未生效规则未启用;当前时间不在规则周期内;终端不在 IP 设置或 IP 分组范围内检查规则状态是否为启用;核对生效时间是否覆盖当前时段;确认测试终端是否命中当前规则范围。
终端连接数仍然过高连接数阈值设置过高;规则对象配置不准确;测试终端未命中该规则重新核对目标终端地址;检查是否选择了正确的 IP 分组;根据实际情况适当下调连接数阈值后再次验证。
正常业务访问变慢或异常连接数设置过低;规则作用范围过大适当提高连接数阈值;缩小规则作用对象范围;确认是否误将正常办公终端或关键业务终端纳入限制。
复制后的规则效果异常复制后未重新检查名称、对象范围或连接数参数在保存复制规则前,逐项核对名称、IP 设置、协议、连接数和备注等参数。
批量删除后无法恢复批量删除前未进行配置备份建议在批量操作前先执行导出备份;如已删除,只能通过导入备份或手工重建规则恢复。
