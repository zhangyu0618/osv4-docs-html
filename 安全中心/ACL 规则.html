ACL规则使用说明

1 概述

ACL（访问控制列表）规则是网络设备中实现精细化流量管控的核心安全功能。它如同网络中的“交通警察”，通过预定义的一系列匹配条件（如源/目的IP地址、端口、协议等）和处置动作（允许或拒绝），对经过设备的网络流量进行筛选和控制，从而实现对网络访问权限的管理、安全威胁的防护以及流量的优化引导。

1.1 核心能力

本功能模块主要提供以下核心能力：

  • 精细化访问控制：支持基于IPv4/IPv6协议栈，对TCP、UDP、ICMP等多种协议的流量进行控制。可精确匹配源/目的IP地址（支持单个IP、网段及分组）、源/目的端口（支持单个端口、范围及分组），实现网络层到传输层的全方位策略定义；
  • 灵活的策略动作与方向：对匹配的流量执行“允许”（转发）或“阻断”（丢弃）动作。可指定规则方向（如“进”、“转发”），并结合“连接方向匹配”实现基于会话状态的智能过滤（如仅允许已建立连接的返回流量）；
  • 优先级调度与时间策略：通过0-65535的优先级数值（数值越小优先级越高）决定多条规则的执行顺序，确保关键策略优先生效。支持基于周期（如按周循环）和时间段的生效时间策略，实现访问控制的定时启停；
  • 可审计性与高效管理：支持为规则启用日志记录，便于安全审计和故障排查。提供规则的添加、编辑、复制、批量导入/导出、启用/停用等功能，极大提升了大规模策略的运维效率。

1.2 适用场景

  • 网络分区与隔离：限制不同部门（如研发、财务）网段之间的互访，或禁止内网用户访问特定高风险外网区域；
  • 服务器保护：在服务器前端部署ACL，仅开放必要的服务端口（如Web服务器的80/443端口），屏蔽所有其他扫描和攻击流量；
  • 合规与审计：满足等保、GDPR等合规要求，对特定用户访问关键系统的行为进行记录和监控；
  • 流量引导与优化：结合优先级，确保关键业务（如视频会议）的流量优先通过，限制或降低非业务流量（如P2P下载）的优先级。

2 参数解释与操作导航

2.1 界面布局

依次点击【安全中心】>【ACL规则】，进入ACL规则页面。

ACL规则页面采用列表式布局，主要展示所有已配置的ACL规则，包含名称、协议栈、协议、动作、连接方向匹配、方向、优先级、源地址、目的地址等核心信息，支持对单条规则的编辑、复制、启用、停用、删除操作，同时支持批量操作。

2.2 ACL规则主页面

ACL规则主页面为访问控制列表规则的管理控制台，以列表形式展示所有已配置的ACL规则，支持通过搜索框快速定位规则，提供添加、导入、导出规则的功能，以及对单条规则的编辑、复制、启用、停用、删除操作，同时支持批量操作（启用、停用、删除），便于高效管理和维护网络访问控制策略。

ACL规则主页面如下图所示：

ACL规则主页面

功能按钮

  • 搜索框：输入关键词（如规则名称、IP地址、协议），快速筛选ACL规则；
  • 添加：打开"ACL规则-添加"配置界面，创建新的ACL规则；
  • 导入：导入本地ACL规则配置文件，批量恢复/迁移已有配置；
  • 导出：导出当前所有ACL规则配置（含名称、协议、动作、地址等参数），便于备份或跨设备复用；
  • 编辑（列表操作列）：修改对应ACL规则的参数（如名称、协议、动作、地址等），界面与"添加"相同；
  • 复制（列表操作列）：复制选中的ACL规则，快速创建相似规则；
  • 启用（列表操作列）：激活该ACL规则（规则立即生效）；
  • 停用（列表操作列）：暂停该ACL规则（规则停止生效），再次点击可重新启用；
  • 删除（列表操作列）：移除该ACL规则配置（需确保无网络流量依赖，避免网络中断）。

2.3 ACL规则添加/编辑页面

点击主页上【添加】按钮，打开添加ACL规则窗口。该窗口为新建ACL规则的界面，用于配置一条全新的访问控制规则或修改现有规则；需设置名称、协议栈、协议、动作、连接方向匹配、方向、优先级、源地址、目的地址、备注等核心参数，支持通过"添加"按钮扩展源/目的地址、端口、VLAN等配置项，还可配置时间策略、日志策略等高级选项，配置完成后点击「保存」即可使规则生效。

功能按钮

  • 保存：点击后将当前配置的ACL规则保存至系统，并立即生效（需确保参数配置无误）；
  • 取消：放弃当前配置，返回上一级页面（不保存任何修改）。

2.4 ACL规则批量操作

在ACL规则列表中通过复选框批量选中ACL规则项，可以批量管理ACL配置，支持全选、启用、停用、删除等批量操作，以及对单条规则的编辑、复制、启用、停用、删除操作，便于批量管理和维护ACL策略。

ACL规则批量操作界面如下图所示：

功能按钮

  • 全选：选中当前页面所有规则（用于批量操作）；
  • 启用（批量）：选中多条规则后，批量激活这些规则；
  • 停用（批量）：选中多条规则后，批量暂停这些规则；
  • 删除（批量）：选中多条规则后，批量移除这些规则。

3 核心运维与操作流程

3.1 配置前准备

在配置ACL规则前，必须进行周密规划，以确保策略有效且避免误阻断正常业务。

  • 网络拓扑与流量分析：明确需要部署ACL规则的设备位置（如核心网关、服务器前端），并分析经过此处的关键业务流量路径。
  • 安全策略规划：遵循“最小权限原则”，明确“允许”和“拒绝”的访问关系。建议先绘制简单的访问控制矩阵。
  • 参数规划表：强烈建议填写以下表格，作为配置蓝图。

参数解释表

参数名称详细说明
规则名称清晰反映规则用途，便于管理。
协议栈根据实际网络选择IPv4或IPv6。
协议根据业务选择，如TCP、UDP、TCP+UDP或任意。
动作核心动作，允许即放行，阻断即丢弃。
方向常用转发。进通常用于控制进入设备本身的流量（如管理流量）。
连接方向匹配除非需要基于会话状态过滤（如仅允许回应包），否则保持关闭。开启后会自动允许已建立连接的返回流量。
优先级关键：数值越小越优先。需全局规划，避免冲突。范围0-65535。

目的地址同上。

备注记录规则目的，便于后期维护。

3.2 标准配置操作步骤

遵循“先允许后拒绝”或“先精确后宽泛”的优先级顺序进行配置。

  1. 访问页面：登录设备管理界面 → 进入【安全中心】 → 点击【ACL规则】。
  2. 添加规则：
  • 点击【添加】按钮，进入配置页面。
  • 填写基本信息：按规划表填写“名称”，选择“协议栈”、“协议”、“动作”、“方向”。
  • 设置优先级：关键步骤：根据全局策略规划，为当前规则设置“优先级”数值。
  • 配置匹配条件：
  • 地址设置：在“源地址”和“目的地址”区域，通过【添加】或【批量】输入IP/网段，或选择已有IP分组。
  • 端口设置：在“源端口”或“目的端口”区域，添加需要控制的端口号或范围。
  • （可选）高级设置：配置“生效时间”、“连接方向匹配”，或勾选“反向匹配”。
  • 保存规则：点击【保存】。新规则默认处于“启用”状态。
  1. 规则排序与验证：
  • 返回列表页，检查规则优先级顺序。可通过编辑规则修改其“优先级”值来调整顺序。
  • 规则从上到下匹配，一旦匹配即执行动作，不再匹配后续规则。

3.3 配置验证与日常维护

  • 验证方法：
  • 连通性测试：从源地址设备，向目的地址和端口发起访问，验证“允许”规则是否生效；或测试“阻断”规则是否成功拦截。
  • 基础连通性测试：
 # 测试ICMP连通性（ping） ping 10.0.0.10 # 测试TCP端口连通性（telnet/nc） telnet 10.0.0.10 3306 # 或使用nc（netcat） nc -zv 10.0.0.10 3306 # 测试UDP端口连通性 nc -zvu 10.0.0.10 53
  • 业务应用测试：
 # 测试Web访问 curl -I http://10.0.0.10：80 # 测试数据库连接 mysql -h 10.0.0.10 -P 3306 -u test -p
  • 日志验证：若规则启用了日志，在【日志中心】查看是否有对应的ACL匹配记录。查找关键词如规则名称、源IP、目的IP等。
  • 会话查看：在设备的状态监控页面，查看是否有符合规则预期的会话建立。检查会话状态、持续时间、流量统计等信息。
  • 日常维护：
  • 定期审计：每季度或业务变更时，审查所有ACL规则，停用或删除过期、无效的规则。
  • 监控日志：定期分析ACL阻断日志，发现潜在攻击或策略缺陷。
  • 备份配置：在进行批量修改前，使用【导出】功能备份当前所有ACL规则。
  • 变更管理：任何ACL规则的新增或修改，应在业务低峰期进行，并做好回滚准备。

4 常见问题与故障排除

问题现象可能原因排查步骤与解决方案
ACL规则不生效，流量未被控制1. 规则未“启用”。 2. 规则“优先级”过低，被更高优先级的规则先匹配并处理。 3. 流量特征未精确匹配规则条件（如IP、端口、协议错误）。 4. 规则方向（“进”/“转发”）设置错误。1. 检查状态：在列表页确认规则为“已启用”状态。 2. 检查优先级：确认当前规则的“优先级”数值是否足够小（优先级高）。检查是否有更高优先级（数值更小）的规则先匹配了该流量。 3. 核对匹配项：使用抓包工具确认流量的真实源/目的IP、端口、协议，与规则条件逐一比对。 4. 核对方向：确认规则“方向”设置是否正确。控制穿越设备的流量通常用“转发”；控制访问设备自身的流量（如SSH管理）用“进”。
误阻断合法业务流量1. “阻断”规则的匹配条件过于宽泛（如目的地址设为任意）。 2. “允许”规则的优先级低于“阻断”规则。 3. 未考虑“连接方向匹配”或“反向匹配”的影响。1. 精确化条件：收紧“阻断”规则的匹配范围，使其只针对明确的威胁流量。 2. 调整优先级：确保“允许”关键业务的规则拥有比泛化“阻断”规则更高的优先级（数值更小）。 3. 检查状态匹配：如果启用了“连接方向匹配”，确保其设置符合预期。例如，一条“允许出站”的规则若开启了连接跟踪，其回应流量会自动允许，无需额外规则。
配置大量ACL规则后，设备性能下降1. ACL规则数量过多，且多为需要逐包检查的复杂规则。 2. 启用了“日志”功能，记录了大量匹配事件。1. 优化规则：合并相似规则，使用IP分组、端口分组简化配置。将最常用的规则置于前列。 2. 减少日志：仅为关键的安全阻断规则启用日志，避免为所有“允许”规则记录日志。 3. 硬件检查：评估设备硬件性能是否满足当前策略规模需求。
“允许”规则已配置，但特定流量仍被阻断1. 存在一条更高优先级的“阻断”规则匹配了该流量。 2. 流量匹配了系统内置的默认安全策略（通常为隐性拒绝所有）。 3. 规则生效时间未到或已过期。1. 优先级排查：这是最常见原因。仔细检查所有优先级更高的规则。 2. 检查默认策略：确认设备是否存在一条低优先级（如63）的“阻断任意”的默认规则。若有，需确保你的“允许”规则优先级高于它。 3. 检查时间策略：确认规则的“生效时间”设置是否符合当前时间。
批量操作（启用/停用/删除）失败1. 选中的规则中存在系统内置规则或相互依赖的规则。 2. 浏览器会话超时或网络不稳定。1. 分批操作：避免一次性操作过多规则，或先排除明显特殊的规则。 2. 刷新重试：刷新页面或重新登录后，小批量重试操作。 3. 查看系统信息：检查设备系统日志，寻找操作失败的具体报错信息。
