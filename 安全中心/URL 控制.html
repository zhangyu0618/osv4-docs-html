URL控制使用说明

1 概述

URL控制是 iKuai OS V4 安全中心中的精细化访问改写与跳转控制功能，主要用于对用户访问请求进行重定向、关键字替换或参数替换处理。管理员可根据业务需要，对特定来源终端、指定访问内容以及特定时间段内的流量应用不同的改写策略，从而实现访问引导、灰度测试、内容替换和策略分流等管理目标。

URL控制页面当前主要由 URL跳转、关键字替换 和 参数替换 三个功能标签组成。三类规则均支持按标题管理、设置匹配模式、配置匹配优先级、限制源地址、指定内网地址、生效周期控制，以及单条或批量维护操作，适合在业务迁移、测试发布、安全引导和访问策略优化等场景中使用。

其核心作用主要包括：

  • URL跳转：将命中的访问请求重定向到新的目标地址，适用于旧地址迁移、访问入口统一和灰度发布等场景；
  • 关键字替换：在访问内容中匹配指定关键字并替换为目标值，适用于访问内容改写和策略引导；
  • 参数替换：对请求中的主键内容进行替换，适用于参数级访问控制、内容分流与定向改写；
  • 差异化生效控制：支持结合源地址、内网设备、时间周期和生效率进行精细化下发；
  • 集中运维管理：支持添加、导入、导出、编辑、启用、停用和删除等维护能力，便于日常配置与批量管理。

2 参数解释与操作导航

2.1 界面布局

依次点击【安全中心】>【URL控制】，进入 URL 控制页面。页面采用多标签页布局，主要包括【URL跳转】、【关键字替换】和【参数替换】三个功能标签。管理员可在对应标签中分别管理不同类型的 URL 控制规则。

2.2 URL跳转

URL跳转功能用于将命中的访问请求重定向到指定目标地址，适用于页面迁移、访问导流、旧地址替换和灰度发布等场景。

2.2.1 URL跳转列表页

URL跳转列表页用于展示当前已配置的 URL 跳转规则，支持查看规则状态及核心字段，并可对规则进行新增、导入、导出和单条维护操作。

URL跳转列表页如下图所示：

URL跳转列表页面

功能按钮说明

  • 添加：用于创建新的 URL 跳转规则；
  • 导入：用于批量导入 URL 跳转规则；
  • 导出：用于导出当前 URL 跳转规则配置；
  • 编辑：用于修改指定规则的参数；
  • 启用/停用：用于切换指定规则的生效状态；
  • 删除：用于移除指定规则。

2.2.2 URL跳转新增页面

点击【添加】按钮，可进入 URL 跳转新增页面。管理员可在该页面中设置标题、匹配模式、优先级、源地址、目的地址、跳转率、内网地址和生效周期等内容，以完成新规则创建。

URL跳转新增页面如下图所示：

URL跳转-新增

参数解释表

参数名称详细说明
标题*用于填写当前规则名称，建议结合用途进行命名。
匹配模式用于选择规则的地址匹配方式，当前可选"精确匹配"等方式。
匹配优先级*用于设置当前规则执行优先级，数值越小优先级越高。
源地址*用于设置触发规则的客户端地址范围。
目的地址*用于设置被访问时触发跳转的原始地址。
跳转率*用于设置规则按比例生效，按百分比跳转至指定页面。
内网地址 - IP/MAC设置用于设置规则仅对指定终端设备生效，支持单个添加或批量添加 IP/MAC 地址。
内网地址 - IP/MAC分组用于选择已创建的 IP/MAC 分组，规则将对该分组内的设备生效。
生效时间*用于设置规则的生效周期，支持三种方式：时间计划、按周循环、时间段。
周期用于在按周循环模式下选择生效的星期与时间段。
注：带*号的参数项为必填项。

功能按钮说明

  • 保存：用于保存当前 URL 跳转规则配置；
  • 取消：用于放弃当前配置并返回列表页面。

3 核心运维与操作流程

URL控制规则的日常运维通常包括需求规划、规则创建、效果验证、状态维护和批量管理等环节。为避免访问异常影响正式业务，建议管理员优先在小范围终端或灰度比例下进行测试，确认规则效果后再扩大应用范围。

3.1 规则创建流程

  1. 根据业务需求确认使用【URL跳转】、【关键字替换】或【参数替换】中的哪一类功能。
  2. 进入对应功能页签，点击【添加】。
  3. 依次填写标题、匹配模式、匹配优先级、源地址、目标内容及生效周期等参数。
  4. 如需限制规则生效范围，可补充配置内网地址信息。
  5. 如需灰度发布，可先设置较低的跳转率进行验证。
  6. 保存规则后，返回列表检查规则状态是否正常。

3.2 规则验证与调整流程

  1. 使用命中规则范围内的终端访问目标地址或内容，验证跳转、关键字替换或参数替换是否符合预期。
  2. 若规则未生效，优先检查匹配模式、优先级、源地址、内网地址及生效周期是否配置正确。
  3. 若规则效果异常，可通过编辑功能调整目标内容、排除值或跳转率，并再次验证。
  4. 多条规则并存时，应重点核查优先级设置，避免规则冲突导致效果不一致。

3.3 批量维护与备份流程

  1. 在列表页中勾选多条规则后，可执行批量启用、停用或删除操作。
  2. 在规则批量调整前，建议先通过导出功能备份当前配置。
  3. 如需跨设备迁移或恢复配置，可通过导入功能重新加载已备份规则。

3.4 使用建议

  1. 建议使用具有业务含义的标题命名规则，便于后续维护。
  2. 关键业务规则应设置更高优先级，避免被低优先级通用规则覆盖。
  3. 涉及访问改写的策略建议先小范围测试，再逐步扩大生效终端或跳转率。
  4. 对于存在例外访问需求的场景，建议合理使用排除值，避免误改写正常访问请求。

4 常见问题与故障排除

问题现象可能原因排查步骤与解决方案
规则配置后未生效规则未启用；当前时间不在规则周期内；终端不在源地址或内网地址范围内；优先级被其他规则覆盖检查规则状态是否为启用；核对周期设置是否覆盖当前时间；确认测试终端是否命中源地址和内网地址；检查是否存在更高优先级规则先被执行。
部分访问请求未发生跳转或替换匹配模式设置不合适；请求内容被排除值过滤；跳转率未设置为全量检查当前规则使用的是精确匹配还是模糊匹配；核对排除值是否覆盖目标内容；检查跳转率设置是否符合预期。
规则效果与预期不一致标题相似规则较多；多条规则优先级冲突；目标内容填写错误通过列表逐条检查同类规则；重新排序优先级；核对目的地址、替换关键字、主键和替换值内容是否准确。
批量导入失败导入文件格式不符合系统要求；内容参数存在格式错误优先使用系统导出的标准文件作为导入模板；检查地址、关键字和参数内容是否符合格式要求。
规则启用后影响正常业务访问跳转地址或替换值设置不当；规则生效范围过大先停用有问题的规则；缩小源地址、内网地址或跳转率范围；修正目标内容后再重新验证。
