功能日志使用说明

1. 概述

功能日志模块是网络设备进行核心服务状态监控与事件审计的集中化管理平台，位于【日志中心】之下。它不同于记录用户行为的“用户日志”，而是专注于记录网络基础服务（DHCP、动态域名、外网拨号）的运行状态以及系统自身的推送通知事件，为管理员提供了洞察网络服务健康度、诊断连接故障、追溯配置变更的专属窗口。

该模块采用统一的标签页布局，集成了四大关键日志维度：

  • DHCP日志：忠实记录局域网内每一次IP地址请求、分配、续约的全过程，是排查终端无法上网、IP地址冲突、地址池耗尽问题的根本依据。
  • 动态域名日志：追踪DDNS（动态域名解析）服务的每一次更新尝试与结果，是诊断域名解析失败、公网IP变更后服务中断的关键线索。
  • 外网拨号日志：记载PPPoE等宽带拨号连接的建立、断开及认证事件，是分析宽带频繁掉线、拨号认证失败等外网连通性问题的第一手资料。
  • 推送通知日志：汇总系统主动发出的各类告警和信息通知，是回顾系统状态变更、确认配置生效、审计安全告警的可靠档案。

通过标准化的“列表展示 + 多维筛选 + 一键导出”操作界面，本模块旨在将分散的服务日志转化为可追溯、可分析、可归档的结构化信息，赋能管理员高效完成服务故障定位、网络变更审计与运维合规检查等核心工作。

2. 参数解释与操作导航

2.1 页面布局与通用操作

功能日志页面采用标签页方式组织不同功能模块的日志。管理员可根据需要切换不同日志页签查看记录，不同子页面在操作习惯上保持一致，通常包含以下通用按钮：

  • 筛选日期：按时间范围筛选日志；
  • 导出：导出当前查询结果；
  • 清空：清空当前日志内容；
  • 帮助：查看页面帮助信息。

日志主列表位于页面中下部，用于展示日志字段及事件内容；显示选项窗口主要用于设置筛选条件或控制列表字段显示。

2.2 DHCP日志

DHCP日志用于记录DHCP（动态主机配置协议）的全流程交互事件（如IP请求、地址提供、分配确认等），帮助管理员追踪IP地址分配轨迹、排查地址冲突/耗尽问题、审计终端接入行为。页面支持筛选、搜索、导出等功能，助力网络IP资源管理与故障定位。

  • 筛选日期：选择时间范围（如“今天”“自定义区间”），筛选指定时段内的DHCP日志，聚焦特定周期的IP分配事件；
  • 导出：将当前日志列表（含筛选/搜索结果）导出为CSV/Excel文件，便于离线分析或存档；
  • 清空：清空当前日志的筛选条件、搜索内容（注意：若未筛选，可能清空全部日志，需谨慎操作）；
  • 显示选项：点击!12 显示选项图标图标，打开显示选项设置窗口；

该窗口为DHCP日志的筛选条件配置界面，支持从消息类型、终端标识（MAC/本地链路地址）、IP地址三个维度设置筛选规则，帮助管理员精准过滤DHCP日志（如仅查看某类DHCP消息、某终端/IP相关的日志），提升日志分析效率。配置完成后，日志列表将仅显示满足所有筛选条件的条目。

3. 核心运维与操作流程

本章节详细说明使用功能日志模块进行日常监控与问题排查的标准操作流程。

3.1 查询与筛选特定服务日志

此操作用于从海量日志中快速定位关注的服务事件。

  1. 选择日志类型：在功能日志页面顶部，根据排查目标点击 【DHCP日志】、【动态域名日志】、【外网拨号日志】 或 【推送通知日志】 标签，切换到对应日志列表。
  2. 进行时间筛选：点击列表右上角的 「筛选日期」，选择预设的时间范围（如“最近1小时”）或自定义起止日期，聚焦问题发生时段。
  3. 使用关键词搜索：在顶部的 「搜索框」 中输入关键词（如DHCP日志中的MAC地址、动态域名日志中的域名、外网拨号日志中的线路名），系统将实时过滤出包含该关键词的日志行。
  4. 启用高级筛选器（以DHCP日志为例）：
  • 点击页面上的 「显示选项」 按钮，选择 「筛选器」 标签。
  • 在弹出的窗口中，可以针对 「消息类型」、「MAC地址/本地链路地址」、「IP地址」 设置精确的筛选条件。例如，要查看某终端（MAC: f6：40：f7：c2：26：63）获取IP的全过程，可在MAC地址筛选中指定该地址。
  • 点击 「恢复默认值」 可清空所有筛选条件，点击外部或完成设置后，列表将自动刷新并仅显示符合条件的日志。

验证方法：观察日志列表，确认显示的结果条数符合预期，且每条记录的关键字段（如MAC、IP）与筛选条件一致。

3.2 自定义列表视图以聚焦关键信息

此操作用于调整日志列表显示的字段，屏蔽无关信息，提升阅读效率。

  1. 进入列设置：在日志列表页面，点击 「显示选项」，然后选择 「列」 标签。
  2. 勾选显示字段：通过复选框选择或取消选择需要显示的列。例如，在分析DHCP地址分配时，可以只勾选 「时间」、「消息类型」、「MAC地址」 和 「IP地址」，隐藏「接口」和「事件描述」列。
  3. 应用与恢复：勾选操作即时生效，页面列表会自动更新。点击 「还原列」 按钮可一键恢复所有列为系统默认的勾选状态。

验证方法：返回日志列表，确认显示的列标题与刚才勾选的选项完全一致。

3.3 导出日志用于离线分析或长期存档

此操作用于将重要的日志数据固化保存，用于生成报告、深度分析或合规留存。

  1. 定位目标数据：首先，利用上述3.1和3.2的流程，筛选并呈现出需要导出的具体日志数据集。
  2. 执行导出：点击列表右上角的 「导出」 按钮。
  3. 保存文件：浏览器将下载一个包含当前列表数据的文件（通常是CSV格式），选择本地路径保存即可。

验证方法：使用电子表格软件（如Excel）打开导出的文件，确认其内容与网页端显示的日志数据完全吻合。

3.4 清空历史日志以释放空间

此操作用于清理已处理完毕或过期的日志数据，保持界面清爽并节省存储空间。 注意：清空操作可能不可逆，请务必先确认数据无用或已完成备份。

  1. 确认数据范围：可通过“筛选日期”功能，确保当前列表显示的都是计划清除的日志。
  2. 执行清空：点击列表右上角的 「清空」 按钮。
  3. 二次确认：根据系统提示，确认清空操作。清空后，当前标签页下的日志列表将为空。

4. 常见问题与故障排除

问题现象可能原因排查与解决步骤
DHCP日志显示大量DHCPDISCOVER但无后续DHCPOFFER，终端无法获取IP1. DHCP服务器服务未运行或异常。 2. 地址池已完全耗尽，无可用IP地址。 3. 交换机端口或网络策略阻止了DHCP广播包到达服务器。1. 检查服务状态：确认网络设备的DHCP服务器功能已启用且运行正常。 2. 检查地址池：在DHCP服务器配置中，查看地址池容量和使用率，必要时扩大地址池范围。 3. 检查日志详情：查看是否有“地址池耗尽”等相关描述。检查网络拓扑与ACL规则，确保客户端与DHCP服务器间二层互通。
动态域名日志频繁显示“更新结果：失败”，详情为“域名错误”或“Access Key无效”1. 配置的域名拼写错误或不存在。 2. DDNS服务商（如花生壳）的账号、密码或密钥（Access Key）配置错误或已失效。 3. 网络设备无法访问DDNS服务商的更新接口。1. 核对域名：在动态域名服务配置页面，仔细检查填写的域名是否正确无误。 2. 验证凭证：登录DDNS服务商官网，确认账号状态及密钥有效性，并在设备上更新为正确的凭证。 3. 检查网络连通性：确保设备能正常解析并访问DDNS服务商的API服务器地址。
外网拨号日志显示“线路”频繁“断开”又“连接”，网络不稳定1. 外网线路物理连接不稳定（如网线、光猫问题）。 2. PPPoE账号密码错误，或运营商侧认证服务器间歇性异常。 3. 运营商设置了会话时长限制，定期强制重拨。1. 检查物理层：检查WAN口网线、光纤连接是否牢固，观察光猫指示灯状态是否正常。 2. 检查日志详情：查看断开前后的日志详情，确认是否为“认证失败”。重新核对并输入PPPoE账号密码。 3. 联系运营商：确认线路质量及账号是否存在会话时长或并发数限制。
预期应收到系统“推送通知”（如设备上线告警），但推送通知日志中无记录1. 推送通知功能（如邮件、微信）未正确配置或未启用。 2. 触发通知的事件等级设置过高，当前事件未达到触发阈值。 3. 通知日志被筛选条件过滤，未能显示。1. 检查通知配置：进入系统设置中的通知配置页面，确认接收方式、接收人信息已正确配置且功能已开启。 2. 检查触发规则：查看相关告警或事件的触发条件，确认当前事件是否符合通知规则。 3. 检查日志筛选：在推送通知日志页面，清除所有“筛选日期”和“搜索框”内容，确认是否能看到更早或其他的通知记录。
